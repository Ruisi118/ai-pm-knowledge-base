# 第一轮：query 质量门

## 判断原则

只判断「题目本身能不能被理解、有没有唯一可推断的意图」，**不判断「这题对模型来说难不难」**。

冷门知识、复杂逻辑、故意设置的反直觉陷阱**都不算缺陷**。「所有模型都对/都错」也不在这一轮处理——那是模型表现层面的信号，留给第二轮，绝不能作为 query 缺陷剔除依据（漏掉共性弱点最常见的原因就在这）。

## 三分类

### 合格
题意清晰，一个具备常识/专业背景的人能读懂「提问者想问什么」，**即便标注员自己也答不出来**。

### 语义缺陷-剔除
需同时满足「表述有问题」+「无法确定唯一合理意图」。具体情形：

1. 题面读不通、真读不懂在问什么（**不是翻译生硬**——生硬但能懂的算合格）
2. 句子截断、多义指代无法消歧、缺关键限定词导致可合理理解为两种以上完全不同的问题
3. 多轮对话缺 history 导致当前 prompt 无法独立成题（如「那第二种呢？」但 history 为空）
4. **结合 history 仍无法锁定唯一指代对象**——「有 history」不等于「能还原意图」。标准是「结合 history 后能否锁定唯一指代对象」，**不能因为 history 非空就放宽判断**
5. **脱离 history 后信息量太薄**（与上一条并列的独立条件，满足其一即判缺陷）——即使能锁定指代，若脱离 history 后 prompt 本身不构成一个具体的、可独立评估/可回答的问题，仍判缺陷。三条细则：
   - **极短追问/指令词**：「那第二个呢」「如果不是呢」「继续」「还有吗」——没有实质内容词
   - **代词是唯一信息载体**：「它」「这个」「上面的方法」是句子唯一实质信息，脱离 history 连问的是什么领域都判断不出
   - **笼统追问句**：结构完整的疑问句（「还有其他办法吗」「这样可以吗」「为什么会这样」），能猜到句式但无法判断指向哪个具体对象
6. **无实际请求的纯陈述/纯信息转发**：只是陈述一件事、罗列信息、贴一段素材（行程草稿、地址电话列表、背景描述），没有任何可识别的任务动词、疑问点或请求动作。**不限定于依赖 history 的场景**，纯独立陈述句同样适用
7. **被要求处理的对象未随行提供**：「把这个总结成表格」但「这个」从未提供、「检查一下我的代码」但代码未贴出

### 敏感请求-需关注
题意清晰可判断，但内容涉及隐私探查/跟踪定位/人肉搜索等敏感边界。

**这不是语义问题，不能用「语义缺陷」处理**。默认**保留进入第二轮**，但走人工 judge 路径——安全边界判断依赖人的价值判断和风险容忍度，量少时人工成本可接受，不必让自动化 rubric 再承担一层安全维度设计的复杂度。

仅当内容已明显越界（具体到能定位真实个人）时才由标注员升级处理，不作为自动剔除规则。

## 不构成缺陷的四种情况（高频误判）

| 情况 | 为什么合格 |
|---|---|
| **话题跳跃** | prompt 本身包含足够具体的实质内容（单位换算、具体代码请求、具体术语追问），即使与 history 话题不相关，仍合格。这一轮筛的是「信息量太薄」，不是「与 history 相关性」 |
| **专业术语盲区** | 标注员不懂 ≠ 题目有问题 |
| **延续性陈述句** | 纠正、追加论断这类陈述句，若能识别出说话人在推进什么，判合格 |
| **「是 A 还是 B」二选一句式** | 只要 A、B 在 prompt 中都已写明、不依赖 history 展开，即视为信息完整。仅当 A 或 B 任一项模糊到无法辨认时，才落入「代词是唯一信息载体」判缺陷 |

## 高误判风险类型

- **陷阱/错误假设类**：区分「故意设置的错误假设」（合格）vs「问题自相矛盾到无法确定原意」（缺陷）。经验法则：**能猜出「应该指出什么有误」就合格；连这个都猜不出才是缺陷。**
- **脑筋急转弯 / 文字游戏**：区分「字面荒谬但有约定俗成解法」（合格）vs「翻译后双关彻底失效」（缺陷，大概率需要看原文）

## 何时需要看原文

默认只看译文 + 元数据，不看原文。四条触发条件：

1. **翻译长度骤降**：译文/原文长度比明显低于同语种同类型中位数，**且**译文读起来语义不完整（两条件同时满足才查）。注意「骤降」应定义为相对同组中位数的偏离，不是绝对阈值——中文压缩率天然高
2. **疑似截断词**：出现「受限于/truncated/字数限制/篇幅限制」等措辞
3. **翻译可能改变题意（反查触发）**：第二轮读回答时，若发现**多个**模型的回答明显在答另一个问题、与译文对不上，且不像单模型能力问题，应反查原文核实译文是否失真。单个模型跑题不算——那是它自己的 `off_topic`
4. **高风险类型抽样**：对翻译/语言能力这类天然高风险的域做 20% 抽样查原文作哨兵；抽样中发现 >1-2 处失真，升级为全量查

## 字段设计

- `quality_flag`：合格 / 语义缺陷-剔除 / 待查原文-已核实合格 / 待查原文-已核实缺陷 / 存疑-待复议 / 敏感请求-需关注
- `quality_note`：一句话备注剔除/存疑/敏感原因（**第二轮回填时会被脚本直接引用，不要写成只有自己看得懂的速记**）
- `checked_original`：布尔，是否实际打开原文核对过

**存疑题不阻塞主流程**：全量跑完后集中做一次复议（隔天回头看，标准更稳）。

## 交接纪律

第一轮剔除的题在交付表里**不能留空白**，但也**不能填判定字段**：

- 填：`是否入选=否`、`rejection_type=query语义缺陷`、`选择理由=【淘汰理由】query语义缺陷：` + `quality_note` 原文（脚本自动取，不手抄）、`stage_status=第一轮剔除`
- **留空**：`n_wrong` / `spread` / 所有第二轮判定字段——这些题从未走过第二轮的门，填了等于伪造判定痕迹

统计淘汰原因分布时，`query语义缺陷` 属**非判定类**，必须与判定类淘汰分开报，否则会把「没参与判定」混进「判定为不入选」。
