# 统计口径纪律

出数字给别人看之前，这几条每条都踩过。

## 1. 分母必须写在数字旁边

同一批数据至少有三个合法分母：

| 分母 | 含义 | 本项目值 |
|---|---|---|
| 全库 | 所有原始行 | 1510 |
| 走完第二轮判定的 | 排除第一轮剔除 + 非判定类淘汰 | 1347 |
| 某子集 | 按模型数/domain/语种切 | 1002 / 345 |

**入选率 276/1510 = 18.3% 和 280/1347 = 20.8% 都对**，但放在同一句话里就错了。

本项目两份对外文档用了不同分母（分析总结按 1510、产出说明按 1347），最后只能在两份文档里**互相注明「不可跨表取数」**。更好的做法是**开跑前就定一个主口径**，其余口径一律显式标注。

## 2. 共线的维度不可归因

本项目 4 模型子集入选率 18.9%、5 模型子集 24.6%，差 5.7pp。看起来像「模型数越多越容易达到 `n_wrong≥2` 门槛」。

**但不能这么说。** 因为有回答的那 345 条**恰好等于 9 个 `专业知识:*` domain 的并集**——5 模型子集 ≡ 专业知识题，4 模型子集 ≡ 通用题。门槛效应与 domain 效应**完全共线，无法分离**。

出这种对比数字前先检查：切分维度和别的维度是不是重合的？重合就只报数字、不报解释，并显式写明「不可归因」。

### 附：依赖阈值的子集比较，必须换一种阈值写法重算一遍

共线只能证明「无法归因」。**更硬的检验是：把判定阈值换一种等价意图的写法，看结论还在不在。**

本项目的入选门是绝对数 `n_wrong >= 2`。换成意图相同的比例门 `n_wrong / n_models >= 0.5` 重算：

| 子集 | 绝对门 | 比例门 |
|---|---:|---:|
| 4 模型（1002 题） | 18.9% | 18.9%（n=4 时两规则等价） |
| 5 模型（345 题） | **24.6%** | **10.7%** |

**差异连符号都反转了**——原本 5 模型子集高 5.7pp，换个写法变成低 8.2pp。48 道「5 模型 / 2 家答错」全部卡在这个差上。

结论：这个 5.7pp 不是「5 模型子集更容易出弱点题」的证据，它**首先是阈值写法的产物**。任何形如「A 组比 B 组高 X」的结论，若 A、B 的组内样本量或判定分母不同，出数前先做这一步。做不了就不要写因果解释。

## 3. 事后归因 ≠ 筛选准则

「哪些特征与高 `n_wrong` 相关」是**对已判定结果的事后统计**，不是判定时用的规则。两者必须分节写、分别标注口径。

换一批数据分布，事后归因的结论要重新验证；判定规则则应保持稳定。混在一起写，读者会以为「细节多的题优先选」是筛选标准，下一批就照着这个去挑题，等于把统计现象当成了因果。

## 4. 样本量小的格子要单独标注

本项目谄媚陷阱识破率表里，某模型只有 16 例，其余模型 80 例。放在同一张表里并列，读者会当成等权重比较。

处理：在表下注明「XX 仅 16 例，不宜并列解读」。**不要因为格子小就删掉行**——那是另一种失真。

## 5. 可信度要分段报，不能只报总体

本项目 `verification_blocked`（打分依赖了无法当场核实的事实点）在入选题中总体 42%，但分段差异极大：

| 批次段 | 入选题中不可核实 |
|---|---|
| 1-150 | 52% |
| 151-200 | 19% |
| 201-229 | 36% |

只报 42% 会掩盖「前 150 批的结果可信度明显更低」这个事实。**执行过程中口径演进过的项目，一定要分段看**——分段差异本身就是口径变化的证据。

## 6. 判定类与非判定类淘汰必须分开

`rejection_type` 会混进两类东西：

- **判定类**：走完全部关卡后判为不入选（单模型孤例、伪分歧、无区分度……）
- **非判定类**：根本没参与判定（第一轮就剔除的、判定为入选但因外部原因在交付层排除的重复题）

做淘汰原因分布时两类必须分开，否则会把「没参与判定」混进「判定为不入选」，分母和构成比同时失真。

## 7. 交付层口径与审计轨迹分离，但要写清楚

本项目 6 道重复题：`results/*.json` 里 `selected` 仍为「是」（真实判定），交付表里写「否 + 重复query」，`review_note` 注明真实结论。

于是有两个都正确的数字：**判定入选 280、净交付 274**。产出说明里两个都要出现，并写明差额来自哪 6 道（列出 id）。**不要为了数字好看只报一个。**

## 8. 复算命令要随文档交付

任何一个对外数字，都要能用一段可复制粘贴的命令从原始结果文件重算出来。产出说明里直接附命令 + 期望输出：

```bash
python3 - <<'EOF'
import json, collections
n = s = dup = 0
t = collections.Counter()
for b in range(1, 230):
    for it in json.load(open('results/batch_%03d.json' % b))['items']:
        n += 1
        s3 = it['step3']
        if s3['selected'] == '是':
            s += 1
            t[s3['selection_type']] += 1
            if it.get('duplicate_of_prior_data'):
                dup += 1
print(n, s, dict(t), 'dup', dup, '净', s - dup)
EOF
# 期望：1347 280 {'区分性弱点':260,'共性弱点':20} dup 6 净 274
```

被问到「这个数怎么来的」时，回答是一行命令，不是一段解释。
